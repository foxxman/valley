# AGENTS.md — контекст для LLM / AI-агентов

Документ для языковых моделей: архитектура, ключевые алгоритмы и правила работы с этим фронтендом.
Человекочитаемый быстрый старт — в `README.md`.

## Назначение проекта

Браузерный **top-down 2D** прототип settlement/exploration игры.

Сейчас реализовано:

- бесконечный чанковый мир (генерация по запросу, 16×16);
- пруды (4-связный blob) + автотайл берега (straight / corner / inner / water);
- каменные гряды (ядро 4–10 камней + обводка осколков 1–2);
- маленькие деревья на траве (~7.5%, непроходимы);
- цветы и пучки травы (~7.5% каждый, проходимы);
- ходьба персонажа (WASD / стрелки; деревья и камень непроходимы);
- камера всегда держит персонажа в центре;
- другие игроки той же игры: тот же спрайт и логин, координаты приходят по WebSocket;
- idle bounce (squash/stretch по вертикали);
- мини-карта 150×150 (правый верх, цвета тайлов, игрок в центре). Цвет точки выдаёт сервер на время подключения, он одинаков для всех клиентов. Чужие игроки в окне карты стоят на своём тайле; если они дальше, точка липнет к краю и показывает только направление. Под картой — тайл текущего игрока (`x`, `y`).
- инвентарь на 20 ячеек (5 в ряд): React-модалка по клавише I. Рюкзак свой у пары игрок + игра. Инвентарь и журнал карты запрашиваются при входе в `/play/:gameId`. Ошибка инвентаря остаётся текстом в модалке и не блокирует мир. Ошибка журнала не пускает в мир;
- сбор четырёх цветов (`flower-0`…`flower-3`) клавишей E. В рюкзаке у них имена «Цветок I»…«Цветок IV» и те же png, что на карте. Пучки травы и кувшинки не собираются;
- разборка дерева или сплошного камня клавишей E, если объект стоит на клетке по взгляду. Один запрос — один удар. Полоска прочности рисуется над клеткой, пока в журнале есть остаток. Десять ударов очищают дерево и кладут 4 древесины (`wood`, иконка `items/wood.png`). Камень держится 20 ударов и кладёт 5 камней (`stone`, иконка `items/stone.png`), а клетка становится травой. Осколки не добываются. Дерево и камень по взгляду важнее цветка под ногами.
- крафт по клавише F: список рецептов. Первый рецепт — сундук (`chest`) за 4 древесины. Сундук падает в рюкзак и не ставится на карту.

Пока **нет**: каналов, сноса прудов, построек, чата, друзей, боя, NPC, инструментов и использования предметов. Журнал хранит текущие слои `terrain`, `tree`, `flora`, `feature`, `durability`. Клиент пишет очистку `flora` при сборе, остаток `durability` при ударе, очистку `tree` у дерева и `terrain = grass` у камня. Слой `feature` на карту не рисуется. Берег по-прежнему считается из тайлов, в журнал не пишется. Сервер не пересчитывает сид: первый удар по клетке без строки снимаемого слоя принимается.
Вход и лобби — React (`src/main.tsx`). Карта — Phaser внутри маршрута `/play/:gameId`. Сид мира, журнал клеток и рюкзак приходят с Go-бэкенда (`../backend`), не из env. Любой вошедший пользователь, который знает id, может присоединиться.
(Есть `ChunkWorld.toSnapshot` / `fromSnapshot` — заготовка под будущее сохранение, включая деревья и flora. Журнал в снимок не входит: он живёт на сервере и накладывается после генерации.)

React — HUD и меню. Игровой цикл — Phaser. Правила карты и выдача предметов — Go API.

## Архитектура

```text
index.html
  └─ src/main.tsx
       └─ React: /login | /lobby | /play
            └─ /play → Phaser.Game(createGameConfig)
            └─ WorldScene
                 ├─ preload()     — текстуры
                 ├─ create()      — ChunkWorld + spawn chunk + Player + follow camera
                 └─ update()      — player; ensure/draw chunks; cull; minimap

Логика мира (без Phaser):
  world/tiles.ts          — TileType, walkability
  world/chunkWorld.ts     — бесконечные чанки, журнал поверх сида, snapshot API
  world/generate-chunk/   — пруды + деревья/flora внутри одного чанка
  world/flora.ts          — виды цветов/травы + маппинг на AssetKey
  world/gatherTarget.ts   — клетка действия: дерево или камень по взгляду, иначе цветок
  world/nodes.ts          — полная прочность разрушаемых объектов
  world/terrainVisual.ts  — water/straight/corner
  map/                    — GET журнала, POST сбора и POST удара

UI:
  ui/Minimap.ts           — HUD-мини-карта (Graphics, scrollFactor 0)
  inventory/              — React-модалка поверх канваса, не сцена Phaser

Сущности:
  entities/Player.ts      — ввод, взгляд, коллизии (isWalkableAt), bounce
  entities/RemoteAvatar.ts — чужой спрайт и логин
  net/channel.ts          — WebSocket присутствия, координат и конверта map
```

### Важные разделения

1. **Логическая карта** ≠ **визуальный тайл**.  
   В чанке `grass | water | stone | stone-shards` + слои `trees` / `flora`. Берег — в `resolveTerrainVisual`.

2. **Данные чанка** живут рядом с игроком. `releaseFarChunks` забывает сгенерированные чанки; тот же сид собирает их снова, затем на клетки накладывается журнал. Сам набор замен `releaseFarChunks` не выбрасывает. Чанки из `fromSnapshot` закреплены и не выбрасываются.  
   **Картинка чанка** — один `RenderTexture`. Далеко от камеры он уничтожается и запекается заново из tiles/trees/flora. После патча клетки уже запечённый чанк уничтожается и рисуется снова.

3. **Phaser** — цикл, камера, ввод, отрисовка. Генерация — чистые функции.

4. Предпочтение в TS: **объекты-словари вместо `switch`**.

## Поток (рантайм)

1. Старт: `ChunkWorld(worldSeed игры)`, в него кладётся журнал (`loadCells`) ещё до генерации. Затем чанк `(0,0)` и соседи, спавн в центре `(0,0)`. Генерация чанка сразу накладывает замены на массив тайлов.
2. Камера: `startFollow(..., 1, 1)`, **без** `setBounds`.
3. Игрок идёт → `isWalkableAt` / `getTileAt` создаёт чанк при первом касании.
4. `update`: `ensureChunksAround` + запекание чанка в текстуру; далеко — destroy текстуры и `releaseFarChunks`.
5. Будущий сейв: `world.toSnapshot()` (tiles + trees + flora) → JSON/сервер; загрузка — `ChunkWorld.fromSnapshot`. Формат снимка не менялся: журнал живёт отдельно и накладывается после генерации.

## Алгоритм генерации чанка

Файл: `src/game/world/generate-chunk/` (вызывается из `ChunkWorld.ensureChunk`).

1. Чанк 16×16 (или `VITE_CHUNK_SIZE`), вся трава.
2. Пруд — с шансом ~40% один 4-связный blob, **inset ≥1** от края; тонкие места срезаются, чтобы у воды был валидный берег.
3. Каменная гряда — с шансом ~50%: связное ядро 4–10 камней + обводка осколков толщиной 1–2 (Chebyshev); без воды/декора на камне и осколках.
4. Чанк `(0,0)`: центр 3×3 без воды/камня/декора (спавн).
5. На чистой траве (кроме спавна): ~7.5% дерево, иначе ~7.5% цветок, иначе ~7.5% пучок травы.
6. Сид чанка = mix(`worldSeed`, `cx`, `cy`) — детерминированно.

## Алгоритм берега (автотайлинг)

Файл: `src/game/world/terrainVisual.ts`.

Только три визуала воды:

| landMask (соседи-трава) | Текстура | Смысл |
|-------------------------|----------|--------|
| 0 | `water.png` | середина пруда |
| N / E / S / W | `shore_straight` | прямой берег |
| N\|W, N\|E, S\|E, S\|W | `shore_corner` | угол: **суша огибает воду** |

Трава всегда `grass.png`. Канал и тупик отдельных текстур не имеют. Внутренний угол — `shore_corner_inner`, если ортогональной суши нет, но есть диагональная.

Вода граничит с травой только через клетку берега (периметр прямоугольника).

### Ориентация (angle 0, по часовой в Phaser)

- `shore_straight`: трава **сверху**
- `shore_corner`: трава **верх-лево**

| mask | angle |
|------|-------|
| N / E / S / W | 0 / 90 / 180 / 270 |
| N\|W / N\|E / S\|E / S\|W | 0 / 90 / 180 / 270 |

**Не ломай** соглашения ориентации без обновления `public/assets/README.md`.

## Персонаж

Файл: `src/game/entities/Player.ts`.

- Ввод: стрелки + WASD.
- Движение с нормализацией диагонали; ось X/Y раздельно проверяются на коллизии.
- Коллизии: 4 угла хитбокса → `world.isWalkableAt` (чанк on-demand) → трава без дерева.
- Bounce: каждый кадр `scaleY` осциллирует (`SQUASH_MIN`…`SQUASH_MAX`), `scaleX = 2 - scaleY` (лёгкий squash/stretch). Работает всегда, не только при ходьбе.
- Пока открыт инвентарь или крафт, `update` не применяет скорость. Bounce продолжается.
- Взгляд: зажатые WASD или стрелки. Если ничего не зажато, остаётся прошлая ось. Если зажаты обе оси, побеждает клавиша, нажатая позже. До первого нажатия взгляд вниз. Наружу отдаётся `{x, y}`, где ровно одна ось равна `-1` или `1`.

## Инвентарь

Модалка — React в `GamePage`, не UI Phaser.

1. При входе на `/play/:gameId` клиент один раз вызывает `GET /api/games/{id}/inventory` (`inventory/api.ts`). Ошибка запроса не блокирует мир: в модалке будет текст ошибки.
2. Клавиша I в `WorldScene` переключает инвентарь, клавиша F — крафт. Escape закрывает открытое окно. Если фокус в `input`, `textarea` или `select`, эти клавиши игнорируются. Открытие одного окна закрывает другое.
3. Флаги `inventoryOpen` и `craftOpen` в registry Phaser выставляет React. Пока любой из них истинен, локальный игрок не ходит.
4. Сетка строится по `capacity` из ответа. В `slots` только занятые ячейки; пустые клетки рисует клиент.
5. Картинка берётся по `iconKey` из `inventory/icons.ts`. У цветов ключ совпадает со slug и ведёт на `flower_0.png`…`flower_3.png`. У древесины ключ `wood` ведёт на `items/wood.png`, у камня ключ `stone` — на `items/stone.png`, у сундука ключ `chest` — на `items/chest.png`. При `quantity > 1` рисуется число. Наведение в ячейке показывает `name` и `description`.

## Крафт

Модалка — React в `GamePage`, рядом с инвентарём.

1. При входе на `/play/:gameId` клиент один раз вызывает `GET /api/games/{id}/recipes`.
2. Клавиша F открывает список. Первый рецепт уже выбран, нажатие на другой переключает цель. Снизу кнопка «Создать»; если предмет создать нельзя, она выключена, причина написана под ней.
3. Слева у строки — картинка, имя и количество каждого ингредиента. Справа — картинка результата. Наведение на неё показывает имя через `ui/Tooltip.tsx`.
4. Кнопка шлёт `POST /api/games/{id}/actions/craft`. Успех подменяет рюкзак. Клиент заранее повторяет серверную проверку места в `craft/fit.ts`: ингредиенты списываются, и только потом ищется пачка или пустая ячейка. Если числа разойдутся, верен сервер.
5. Сундук создаётся, но не ставится и не открывается.

## Журнал карты, сбор и рубка

1. После загрузки игры и до `mountGame` клиент один раз вызывает `GET /api/games/{id}/map`. В ответе только изменённые клетки. `null` в слое — слой очищен. Слоя в объекте нет — его не трогали.
2. `ChunkWorld` хранит замены отдельно от чанков. `ensureChunk` сначала генерирует клетку из сида, потом подменяет слои. `flora` — строка или `null`. `terrain` — строка `TileType`. `tree`: `present` или `null`. `durability` — десятичная строка остатка; в тайл она не рисуется, полоску берёт сцена из `damagedCells()`. `feature` пишется в чанк и не рисуется. Незнакомое значение слоя остаётся в наборе замен. Очищенный `tree` прячет полоску, даже если число прочности ещё лежит в заменах. У камня полоска видна, пока клетка ещё камень и в журнале есть остаток.
3. Клавиша E (`JustDown`) игнорируется, пока открыт инвентарь или крафт, фокус в `input` / `textarea` / `select`, или предыдущее действие ещё не ответило. Цель на соседней клетке по взгляду: сначала дерево (`kind: "tree"`), иначе сплошной камень (`kind: "stone"`, не осколки). Оба идут в `POST .../actions/strike`. Иначе цветок `flower-0`…`flower-3` под центром спрайта или на соседней клетке по взгляду (`POST .../actions/gather`). Иначе E ничего не делает. Рамка цели рисуется каждый кадр.
4. Успешный сбор подменяет инвентарь в React и клетку в `ChunkWorld`, затем запекает чанк заново. Цветок не прячется до ответа сервера. Успешный удар применяет клетку сразу. Чанк запекается заново, только если в клетке есть `terrain`, `tree` или `flora`. Один `durability` двигает полоску и текстуру чанка не трогает. Рюкзак подменяется, когда в ответе есть `capacity`: у сбора он есть всегда, у удара — только при `broken: true`. Конверт WebSocket `map` применяет ту же клетку у всех, включая автора; повтор безвреден. `already_taken` без клетки в теле ошибки локально клетку не чистит: её принесёт конверт победителя или следующая загрузка журнала.
5. Если чанк выгрузили и сгенерировали снова, очищенный цветок, срубленное дерево, добытый камень и остаток прочности не пропадают: замена переживает `releaseFarChunks`. Полоска рисуется заново из журнала при входе в сцену.
6. Полная прочность лежит в `nodeDurability` (`world/nodes.ts`): дерево 10, камень 20. Сервер шлёт только остаток. Полоска — один `Graphics` поверх чанка, ширина равна доле остатка от прочности этой клетки. Цвета: больше половины зелёный, больше четверти жёлтый, иначе красный.

Перенос между ячейками, инструменты и использование предметов не реализованы.

## Правила для агентов при изменениях

1. **Не смешивать** логический тип тайла и текстуру берега — берег только в `terrainVisual`.
2. Новые типы местности: сначала `TileType` + генерация + walkability, потом визуал/автотайл.
3. Новые текстуры: файл в `public/assets/{soil|water|stones|vegetation|items}/`, ключ в `assets.ts`, описание в `public/assets/README.md`. `items/` — картинки рюкзака, которых нет на карте.
4. Не тащить React в игровой цикл Phaser; UI — отдельно, когда понадобится.
5. Не коммитить секреты; `.env` в gitignore, образец — `.env.example`.
6. Язык общения с пользователем репозитория — **русский**; код/идентификаторы — английский.
7. Перед крупным рефактором — уточнить у пользователя (особенно смена генерации/автотайла).
8. После правок TS — `npm run build` (включает `tsc --noEmit`).
